# Review checklist for Microsoft 365 and Microsoft Security work products

This file describes how a partner's draft, Copilot answer, script, query, configuration description or licensing proposal about Microsoft 365 or Microsoft Security is reviewed. A review finds what is wrong, shows the evidence and gives the fix. It does not rewrite work that is correct.

## Review verdicts and finding format

A review of a Microsoft 365 or Microsoft Security work product ends with one verdict.

Ship: no finding that would mislead a customer, break a tenant or breach a rule.
Fix first: findings exist that are fixable before use; the list says which.
Stop: a finding makes the work unsafe or wrong at its core, such as a destructive script, a contradicted licensing claim at the centre of a proposal, or customer personal data in a marketing draft.

Each finding has four parts: where (paragraph, line or setting), what is wrong, the evidence (official page and the sentence that contradicts it, or the observable behaviour), and the fix. A finding without evidence is reported as a question, not as a finding.

## Reviewing a marketing draft or a Copilot answer about Microsoft products

A marketing draft or an answer generated by Copilot or another artificial intelligence (AI) tool about Microsoft products is reviewed claim by claim.

Check: every product and plan name is current and written as Microsoft writes it, with no "M365" and no retired names such as "Azure Active Directory" or "Microsoft 365 E5 Security" without "formerly".
Check: every entitlement claim ("Business Premium includes X") is confirmed in the service description, including what the plan is added on top of.
Check: every number has a named source; prices carry market, term, billing plan and price list date; promotions carry an end date and an official source.
Check: preview features are not described as available.
Check: no partner price, incentive rate or margin appears in customer-facing text.
Check: regulatory claims name the regulation and the specific obligation, and no product is said to make a customer compliant by itself.
Check: the register fits the market and the language reads as composed, not translated.
Check: hype words, filler openings, emojis, exclamation marks, em dashes and closing summaries are absent.
Output: the corrected passages, a change list with reasons, and the claim ledger.

## Reviewing a PowerShell script, Microsoft Graph call or KQL query for Microsoft 365

PowerShell scripts, Microsoft Graph calls and Kusto Query Language (KQL) queries are reviewed by reading them. The reviewer does not run them against a customer tenant.

Check: every cmdlet, parameter and module name exists in current Microsoft documentation. Modules have been retired and replaced, for example the Azure Active Directory (Azure AD) PowerShell modules in favour of the Microsoft Graph PowerShell software development kit (SDK); a retired module is a finding.
Check: destructive or wide-reaching commands (Remove-, Set-, Disable-, Revoke-, bulk updates, -Confirm:$false, -Force) are flagged with what they change and a safer first step, such as a -WhatIf run or a read-only query that lists affected objects.
Check: Microsoft Graph permission scopes follow least privilege; read scopes are used when the task only reads.
Check: secrets, client secrets, passwords and tenant identifiers do not appear in the script text.
Check: Kusto Query Language (KQL) queries for Microsoft Defender advanced hunting or Microsoft Sentinel use table and column names that exist in the current schema, filter by time first, and limit results.
Check: the script states its prerequisites: module, version, role, and whether it runs in Windows PowerShell or PowerShell 7.
Output: verdict, findings, the corrected script, and the exact read-only command to test it in a test tenant first. Anything not executed is labelled untested.

## Reviewing a Microsoft 365 security configuration description

Configuration descriptions, such as a Conditional Access policy set, an Intune compliance baseline or a Defender for Office 365 policy plan, are reviewed against Microsoft documentation and safe rollout practice.

Check: Conditional Access policies start in report-only mode, exclude emergency access accounts, and do not lock out administrators; the licence needed (Microsoft Entra ID P1 or P2) is present for every targeted user.
Check: Intune compliance policies have a grace period and a communication plan before devices are blocked.
Check: Defender for Office 365 policies use Microsoft's preset security policies or state why custom policies differ.
Check: features that monitor employees have a works council or employee consultation step in markets that require one.
Check: every feature named is licensed for the users it targets, per the service description.
Output: verdict, findings, a corrected rollout order, and what to test in a pilot group.

## Reviewing a Microsoft licensing proposal or quote

A Microsoft licensing proposal is reviewed for correctness before it reaches the customer.

Check: the base plan and each add-on are compatible, and prerequisites are met for every user.
Check: the seat count respects plan caps read from the current Microsoft page.
Check: mixed-licence effects are addressed, such as users left without Conditional Access or devices left without endpoint protection.
Check: the commitment term and billing plan match the customer's renewal and the partner's new commerce rules.
Check: the proposal states what is not included and what the customer still needs.
Check: prices in the proposal come from the partner's current price list for the customer's market.
Output: verdict, findings, and the corrected line items.

## Common errors found in Microsoft Security work products

These errors appear again and again in partner content and AI-generated answers about Microsoft Security.

Error: a retired product name presented as current.
Error: "includes" without the base plan, so an add-on reads like a standalone product.
Error: a Plan 2 feature attributed to Plan 1, or Defender for Endpoint tiers mixed up with Defender for Office 365 tiers.
Error: a preview feature sold as available.
Error: a United States list price used in a European market.
Error: a tenant-level service described as covering all users without licences.
Error: a script that uses a retired PowerShell module or an over-broad Microsoft Graph scope.
Error: a Conditional Access plan with no exclusion for emergency access accounts.
Error: a statistic with no named source, or a vendor-commissioned study quoted without naming who commissioned it.
